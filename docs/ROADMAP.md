# Delivery phases

Weeks are engineering phases, not calendar waits. The user authorized **through Week 4**, strictly after Week 3 completion. Always perform preflight before starting/resuming a phase. Week 4 is the stopping boundary; features freeze at the equivalent of Day 24.

| Phase            | Deliverables                                                                                                                                                                                                                  | Exit evidence                                                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 — Foundation   | Workspaces/configuration; Auth0; MongoDB models; owned saved-sample CRUD; learning screens; CI/deployment setup; provider access probes                                                                                       | Local authorization/persistence/browser/static checks; live login and hosted smoke evidence or explicit external blockers; Week 1 handoff      |
| 2 — Generation   | Official Gemini adapter, validated outline and on-demand lessons, durable job leases/retries/recovery, cached reopening, generation UI, rich code/quiz handling, technical/nontechnical/broad-topic evaluation                | Real valid saved outline/lesson when keys exist; invalid output never ready; duplicate/failure/cache/ownership tests; Week 1 regression checks |
| 3 — Enhancements | Cached embeddable YouTube search, Hinglish transcript, configurable TTS, durable owned audio, multi-page single-lesson PDF export, idempotent completion/progress                                                             | Enhancement failures isolated; ownership/cache/playback checks; long PDF evidence; prior regressions                                           |
| 4 — Submission   | Critical journey repair, responsive/accessibility/reliability verification, production deployment and fresh-clone setup, accurate README/screenshots/resume bullets, five-minute demo script/shot list/video when tools exist | Actual hosted login/deep-link/persistence smoke, CI and artifacts; explicit incomplete external assets; feature freeze                         |

Weeks 1–3 are complete locally and preserved. Week 4 reviews and verifies the whole implementation, repairs concrete defects, and prepares reproducible setup, deployment/CI configuration, README/screenshots and resume/demo assets. Live Gemini/YouTube meaning/pronunciation, actual Auth0 login, application database, public URLs, hosted CI and narrated recording require external setup. Missing required assets keep full submission incomplete. After the feature freeze, only defects, verification, documentation and authorized external delivery remain.
